# Sisonke Escrow

A USDC escrow smart contract on Stellar (Soroban). A payer locks Testnet USDC for a recipient
until a deadline; an optional arbiter, chosen by the payer at creation, can divide the money if
either side opens a dispute before the deadline. Funds only ever go to the escrow's own payer or
recipient, each escrow pays out exactly once, and the admin cannot perform any escrow action.
**Until `lock_upgrades` is called, the admin can upgrade the code instantly**, so trust in an
instance is trust in its (ideally multisig) admin; see [docs/UPGRADES.md](docs/UPGRADES.md).

This phase is the contract and its scripts only; the web app comes later.

## In one paragraph

`create` + `fund` (or `create_and_fund`, one signature) lock the amount. The payer can `release`
it to the recipient at any time; the recipient can `refund` it to the payer at any time; after the
deadline the payer can `reclaim` it, unless a dispute was opened first. With an arbiter, payer or
recipient can `dispute` before the deadline, after which only the arbiter's `resolve` (any split),
a payer release or a recipient refund can close it. An unfunded escrow can be `cancel`led.

## Make targets

Needs Rust 1.99.1 with `wasm32v1-none` (from `rust-toolchain.toml`), the `stellar` CLI 28.x and
Node ≥ 22.18.

| Target | What it does |
|---|---|
| `make build` | `stellar contract build --package sisonke-escrow` |
| `make fixture` | Rebuilds the upgrade fixture and refreshes `contracts/sisonke-escrow/testdata/upgrade_fixture.wasm` |
| `make test` | Builds, then `cargo test -- --include-ignored` (includes the compiled-wasm tests) |
| `make test-fast` | `cargo test` without the compiled-wasm tests |
| `make soak` | The model test with 300 random seeds |
| `make lint` | `cargo fmt --check` and `cargo clippy --all-targets -D warnings` |
| `make check` | `lint` + `test` |
| `make deploy` | Deploys to Testnet, writes `deployments/testnet.env` |
| `make upgrade` | Upgrades the deployed contract in place (`WASM=`, `MIGRATE=1`) |
| `make upgrade-demo` | Testnet upgrade proof on a separate throwaway instance |
| `make bindings` | TypeScript client for the deployed contract |
| `make e2e-setup` / `make e2e` | Testnet accounts and USDC, then scenarios A–G with every tx hash |

## Testnet run order

1. `make deploy`: deploys and writes `deployments/testnet.env` (refuses to overwrite it without `FORCE=1`).
2. `make e2e-setup`: creates the four e2e accounts in `scripts/.env` (git-ignored), funds them with
   Friendbot, adds USDC trustlines and buys the payer's USDC on the Testnet DEX. Works before step 1 too.
3. `make e2e`: scenarios A–G against the deployed contract; writes `docs/TRANSACTIONS.md` and
   `deployments/testnet-e2e.json`, and exits non-zero if any row fails.
4. `make upgrade-demo`: the upgrade proof on a separate throwaway instance; appends a row to
   `docs/UPGRADES.md`. Leaves 1 USDC stranded on that instance (see UPGRADES.md).

## Testing

146 tests in `contracts/sisonke-escrow/src/test/`, one module per concern (lifecycle, duplicates,
auth, dispute, validation, accounting, index, events, admin, upgrade, ttl, model, wasm), plus an
adversarial suite (`adversary.rs`) that attacks the contract with real money at stake. Auth tests
use `mock_auths` for exactly one signer, never `mock_all_auths`. The model test runs random
operation sequences against a plain Rust reference model and checks the invariants after every step.
